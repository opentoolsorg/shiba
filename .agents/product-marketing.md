# Shiba product marketing context

## Audience and positioning

Shiba is an AI employee workspace for solo builders and teams doing the work behind a company: engineering, design, marketing, sales, operations, finance, research, and revenue work. Lead with the task and useful output, rather than the coding harness or cloud architecture.

Use a calm, direct voice. Describe a launch brief, account research, design specification, code change, operating checklist, or draft budget using supplied figures. Avoid promises of growth, accuracy, autonomy, or integration coverage that the product has not demonstrated.

## Product truth for this branch

- Built-in employee templates: Engineering, Marketing, Research, Operations. Other responsibilities use custom employee instructions; role examples are not proof of built-in presets.
- Repository execution requires a GitHub repository even for non-code work. Explain it as the work's context and a place for files, without hiding the requirement.
- Users review the requested action before approving execution and review results afterward. External publishing is a separate, supported/configured action.
- Finance and revenue examples concern draft analysis or documents from supplied information. Do not claim bookkeeping sync, payroll, payments, financial correctness, revenue outcomes, or autonomous company management.
- The homepage demo is a simulation, not a live run. Source code and local tests do not establish live model/provider/GitHub acceptance.
- Open-source software is free to self-host. Hosting and model usage are paid to the configured providers.

Everyday docs explain what to do next. Operator setup, API schemas, source paths, environment variables, and detailed verification records belong in their own reference pages.
