# Isolated Stripe read design — not enabled

The Stripe lane is separate from OpenConnector scheduled-read grants. It defaults off and requires an explicitly configured Stripe-only 32-byte hexadecimal Worker secret, native dashboard route, scheduler integration and migration 0027 before use. This code creates no key or account and has not been tested with a real Stripe account.

The separate native-owner grant uses a durable state machine. A creator selects an exact Stripe account ID, test or live mode, fixed operation, creation interval, page limit, expiry and call/byte limits. A restricted read-only key must be encrypted in Worker-only storage and never returned by the API, logged, put in a URL, or passed to an agent or container. The owner must attest the key is restricted to the required read permissions; a key prefix or an account lookup cannot prove its scopes. Key rotation, owner membership changes, revision changes, expiry or revocation invalidate the exact grant. A generated SHA-256 pin covers the executable lane sources and migration and is bound into each reviewed grant; a changed pin blocks its further reads and report retrieval until a new grant is reviewed. Account verification must use a fixed account endpoint and compare the returned account ID; its response alone does not prove mode. The key prefix and each response's `livemode`, when supplied, provide separate mode evidence.

Before dispatch, the lane atomically reserves quota and a durable occurrence, and rechecks the original native owner and exact grant after asynchronous work. Unknown outcomes hold capacity and cannot be retried automatically. Reads use a fixed HTTPS origin and methods, an explicit Stripe API version, no redirects, a 32 KiB body cap and five-second deadline, and response projection before persistence. The initial account verification consumes one call. A grant allows at most eight calls, lasts at most 28 days, and repeats the same fixed creation interval daily; late occurrences over 15 minutes are skipped. Only the original currently authorized owner may read a private report. Slack delivery needs separate consent.

The standalone helper pins Stripe API version `2025-10-29.clover`, constructs a single page of either [invoices](https://docs.stripe.com/api/invoices/list?api-version=2025-10-29.clover) or [balance transactions](https://docs.stripe.com/api/balance_transactions/list?api-version=2025-10-29.clover) for one explicit interval of at most 31 days and up to 25 rows, and projects accounting fields. It can sum captured balance rows by currency in integer minor units and validates each row's amount minus fee equals net. These sums describe only captured rows: pagination and dataset completeness remain unknown. They are not a cross-source reconciliation, total revenue, MRR, churn, full ledger, or business-success claim. A reconciliation requires explicit stable source identifiers and reviewed matching semantics; no cross-source match or currency conversion is inferred here.

The isolated credential helper derives a Stripe-specific encryption key and authenticates workspace, native account, credential ID, revision, Stripe account, mode and expiry as associated data. Its tests use only synthetic keys. The helper alone is not an authorization or persistence system and does not establish a key's provider-side permissions.
