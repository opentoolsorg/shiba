# Control plane live acceptance prerequisites

This is an operator checklist for a later authorized test, not evidence that a cloud run passed. The November 3 audit inspected repository source, deployment configuration and workflow guards. No deployment, cloud workload, model inference or Slack message was executed in this audit. Actual deployed Worker values, repository secrets and installed Slack grants were not inspected. They are unknown, rather than confirmed missing.

The managed executor reported current observations with no configured secret bindings, runtime variables or outbound identities. That describes this executor's declared setup. It does not establish the credential state of an existing Worker, GitHub Actions environment or separate connected application.

Exports use a seven-day Worker HMAC download capability, not an S3 presigned URL. No S3 endpoint or S3 credential is required. |

Built-in dashboard authentication alone does not enable this Access-specific canvas. |
| Optional repository publication | A separately permitted test repository and human-approved immutable proposal, using `GITHUB_TOKEN` or the configured GitHub App fields. Repository-scoped container egress remains read only. Initial execution approval does not authorize publication. |

The Worker and preview deployment workflows now forward `ARTIFACT_SIGNING_KEY` from repository secrets and `SLACK_CANVAS_OWNERS` from repository variables. The Worker workflow also forwards `INTERNAL_SIGNING_KEY`, matching the existing preview workflow. An unset canvas policy remains disabled. This fixes source wiring; it does not provision any value or confirm a deployment.

The managed Access configuration also permits the signed `/api/artifacts/download` route to reach the Worker's capability validation. Other artifact and canvas routes keep their existing identity checks. Cloudflare documents [path-specific application policies](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/app-paths/) and [Bypass behavior](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/). The bucket remains private, and invalid or expired capabilities are rejected by the Worker. This configuration has not been applied or tested on a live host.

## Acceptance evidence to retain

1. Record the exact Worker revision, image digest, test account and selected model route before execution. Queue an ephemeral `workspace:<id>` task and retain proof that no sandbox starts before a named human approves the frozen task.
2. Produce text, binary and zero-byte output under the run's `out/` directory. After completion, fetch the delivered archive and compare its digest and file entries. Retain failed upload, tampered capability, expired capability and wrong-object responses. Confirm the outer host policy lets a valid capability reach the Worker without making the private bucket public.
3. Run bounded Explorer, approved Fixer and Reviewer turns. Record real facet identity, denied guessed/nested routes, timeout cancellation and structured observations. Inspect an actual container to establish that managed provider credentials remain outside it.
4. Watch the same exact run as two independently authenticated allowed identities. Disconnect and reconnect a browser, compare durable sequence/cursor replay, revoke a viewer and verify reconnect denial. Keep source execution transport recovery as a separate result: retained room replay does not prove that a lost CLI process was reattached or that every source byte survived.
5. In the explicitly permitted Slack conversation, verify persona names, stable status edits, exact canvas links and buffered author-attributed messages. Have a permitted human approve once; use a distinct unauthorized identity to verify denial with zero run or approval effects. For a publication test, approve the separate frozen publication action and verify the later PR link appears in the already open canvas.
6. Retain the source thread's actual completion delivery and archive or PR link. Exercise a slash command separately if private ephemeral completion is in scope. Record uncertain external responses without blindly retrying them.

7. During an approved native harness run, separately interrupt the reader RPC, evict the child facet and restart the parent while the original container survives. Retain the original signed expiry, generation, job ID, container identity, raw source sequence and redacted room acknowledgment. Prove there is no second START, setup replay or duplicate retained terminal event, including a lost append response and an unfinished secret-bearing line. Interrupt setup and settlement separately and verify unknown status and cleanup. Stop or replace the container and verify explicit loss with no fresh execution. These are required live checks; local controller fixtures do not satisfy them.

Spend execution remains out of scope until the user supplies the pending provider, operation and amount/currency decision. Do not substitute a generic run approval for a payment approval.

## Existing scripts and limits

`pnpm test:live` currently runs TypeSafe inference tests. It is not a Cloudflare Sandbox, R2 or installed Slack acceptance suite. `pnpm test:ephemeral` deploys and later destroys a stage; its smoke criterion is only Worker reachability, including an authentication challenge. Do not run it under a no-deploy instruction. `pnpm selfhost:smoke` disables Containers and proves local boot only. The browser and integration evidence described in [the implementation report](control-plane-upgrade.md) uses local or synthetic adapters and says so.

The `build:validate` label triggers both full CI and the preview deployment workflow. Full CI has no manual dispatch or callable workflow entry. A push alone does not start it. Do not add or toggle the label while deployment is forbidden.

There is a supported partial CI alternative: manually dispatch the existing Desktop workflow on `feat/prince-multi-agent-control-plane`. Its branch job runs desktop typing, lint, unit/Electron tests, the root build, local mock journeys and unsigned packaging with publication disabled. The tag-only desktop release job cannot run for this branch. It uploads ordinary CI artifacts and does not start a deployment chain. This does not run the full backend/frontend verification gate. Remote results must identify the exact run head and workflow scope separately from the local gates.

The operator command is `gh workflow run desktop.yml --repo opentoolsorg/shiba --ref feat/prince-multi-agent-control-plane`. GitHub [manual dispatch](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow) selects the branch tip; verify the resulting run's `head_sha` before calling it exact-head evidence. [Rerunning](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs) an older run retains its old SHA and cannot verify a new commit.

Cloudflare CLI execution now has a container-local journal and a same-job read/reattach protocol. Local tests cover lost launch responses, surviving processes, source sequences, corruption, bounds and cancellation. Prepared parent/facet recovery now retains the exact signed dispatch and runtime capsule and reattaches to the existing SDK run. Durable room acknowledgment and deterministic redacted receipts survive replay and display-history pruning. The supported `onChatRecovery` hook permits only the prepared harness or a cached complete result, and declines setup or settlement replay. See [execution recovery boundaries](control-plane-execution-recovery.md) for the implementation and smallest remaining safe steps. No zero-loss guarantee is claimed across container instance loss, and no live transport or eviction acceptance was run.
