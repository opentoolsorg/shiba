# Bounded native HubSpot deal reads

This optional lane defaults off and requires a separate Worker-only HubSpot encryption secret and native authenticated owner. The owner supplies an existing appropriate static single-account or private-app bearer token, exact numeric portal ID, up to 25 explicit deal IDs and three distinct internal property names. The token is encrypted with a HubSpot-specific key domain and bound to the native owner, account, revision and expiry. It is never returned, placed in a URL, passed to an agent, or used with OpenConnector or MCP credentials. No account or credential is created by this feature.

The owner attests that the token is appropriate for read-only deal access. A successful request does not establish the token lacks write permissions. The implementation sends only a fixed account-details GET and a fixed deal batch-read POST; it offers no generic query, URL, write or proxy. The account response must match the selected portal and provide currency and timezone, which become part of the verified contract and require a separate review before enabling. One account-verification request consumes a reserved call. A grant lasts at most 28 days and at most eight total calls. Each scheduled occurrence uses one fixed selected-deal request, five seconds and 32 KiB. Unknown or interrupted outcomes hold capacity and are not automatically retried. A late occurrence more than 15 minutes old is skipped.

The batch response must be HTTP 200 and `COMPLETE`, with no errors, only requested distinct deal IDs, and all three selected property keys containing strings or null. Extra provider fields are discarded before persistence; the known bearer is rejected if echoed in the serialized result. Missing selected records are not fabricated. The private report cites the exact selection, account, capture time and bytes, grant revision and generated application-source digest. Dataset completeness remains unknown, even for a complete response. A current native owner may review or revoke the grant, including after the feature is disabled; local copies of private reports cannot be retracted.

The implementation follows HubSpot's [account details](https://developers.hubspot.com/docs/api-reference/legacy/account/account-information/get-account-details), [deal batch read](https://developers.hubspot.com/docs/api-reference/legacy/crm/objects/deals/batch/get-deals), and [single-account static authentication](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/authentication/overview) documentation. Legacy private-app creation has sunset; this feature does not recommend creating one. It accepts an already appropriate user-provided token and does not establish account-specific compatibility or permission scope from fixtures. No provider request, credential, account, deployment or model call was made by the local tests.
