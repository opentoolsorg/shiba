# Standing Slack delivery for scheduled comparisons

This optional, default-off family requires `FOUNDER_RECONCILIATION_SLACK_ENABLED=true`, the existing enabled reconciliation schedule, both currently authorized source grants and an active managed Slack installation. It consumes only completed `frr_` results from one exact `frs_` schedule. It never starts a provider read, creates a reconciliation, invokes a model or borrows an OAuth or Stripe Slack disclosure grant.

The original verified native owner selects a still-private completed scheduled sample, exact linked room and Slack team/channel/thread, one to eight sends no greater than the schedule's remaining comparisons, and an expiry bounded by the schedule, token and 28-day limits. The server freezes the original owner UUID and membership, schedule digest, exact two source grant contracts and executor pins, mapping, fixed selections, cadence, cutoff, comparison and source limits, destination installation generation/version/token revision, room audience and new renderer policy. The original owner must explicitly disclose future combined data to all current and future people able to read the selected Slack channel/thread. A different configured native human manager who is a current room reader must independently approve the same digest and sample. Both decisions require a current verified native cookie session and database session; no model or scheduler can approve either decision.

`reconciliation-qualified-rows.v1` is a separately reviewed deterministic projection, not the complete private report. It includes the schedule and result IDs/digests, source grant/account/receipt identifiers and digests, selected HubSpot deal IDs, both capture timestamps, Stripe's fixed created interval and pagination indicator, and every projected comparison row including IDs, status, currency, minor-unit values and differences. Sources are independently timed, bounded and fixed-period; coverage and business success remain unknown. It makes no payment, complete-ledger, revenue, MRR or churn claim. Slack escaping is applied; content above 3,500 UTF-8 bytes is blocked rather than truncated or summarized by a model. The complete source reports remain private.

The sample, both source receipts and source graph must remain current through the original 15-minute review deadline. After activation, expiry of the illustrative sample does not extend access to that sample or revoke a still-current future grant. Only a newly completed result created strictly after the second human approval can be delivered; samples and earlier results are never caught up. Pausing, revoking, source or membership changes, room/link changes, installation rotation, code-pin changes or disabling the flag block future delivery. A message already accepted by Slack cannot be retracted by this grant.

The original shared `founder_automatic_slack_deliveries` ledger is the per-result/destination and unknown-outcome latch across OAuth, Stripe and reconciliation families. Migration `0034_founder_reconciliation_slack.sql` adds a separate grant table and symmetric active-destination exclusion triggers without changing existing grant semantics. One atomic claim consumes a bounded send slot before bot verification. A lost or expired send becomes unknown and is never automatically retried; the destination remains blocked across families. The final D1 proof binds both source receipts, their exact bytes and hashes, parent schedule and source pins, original native owner, approver, audience, destination, reservation and deadlines. A synchronous check follows immediately before one fixed Slack POST.

The generated reconciliation Slack source/renderer/contract pin covers its source adapter, standing store, tick and shared Slack escaping implementation. Changes to these covered files require regenerating the pin and invalidate old grants; owners and managers must review new consent. The independently pinned HubSpot, Stripe, reconciliation and schedule executors remain required as well. Pause/revoke returns only nonfinancial grant metadata and remains available to the current owner with a verified native session when the feature or source is unavailable.

The API is `/api/founder-reconciliation-slack`: GET discovers current destinations and minimal grant metadata, GET `/arsg_<id>` reviews a current grant, POST to the root prepares, and POST `/arsg_<id>/{disclose,approve,pause,revoke}` records explicit decisions. Fixture tests use local SQLite and fake provider/Slack transports. They do not establish live provider, Slack, deployment or billing behavior.
