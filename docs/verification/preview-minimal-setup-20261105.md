## Native enrollment product boundary

At the reviewed revision, new accounts are created with `emailVerified: false`. The [auth implementation](../../packages/auth/src/better-auth.ts) deliberately skips bootstrap verification email and permits verification only for invited policies. The new personal owner and workspace connector authority require a verified native account. Consequently, adding sender configuration does not by itself make a fresh bootstrap owner eligible for those new features.

The currently supported test route is an explicitly invited and verified native member, or invited verified admin where management is required, with the necessary workspace authority. A first bootstrap owner needs an explicit reviewed verification contract before it can use those routes as that same account. This is a product enrollment gap, not merely a missing key. Never mark an email verified by manually editing D1 or treat Cloudflare Access/email matching as a substitute for the immutable native identity. Existing account state has not been inspected.
