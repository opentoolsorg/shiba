## Live updates

Dashboard subscribers use the WorkspaceEvents Durable Object WebSocket at `GET /api/workspaces/:id/events`. When that binding is absent, the same path falls back to a heartbeat event stream. Publishers call `publishWorkspaceEvent` from `apps/backend/src/platform/workspace-events-do.ts` with the shared event shape and an optional audience of user ids or a room id.

## Run thread

`packages/shared/src/run-thread.ts` projects an acknowledgement, milestone updates (result, decision, blocker), inline approvals with a frozen payload, a final denial, a question with up to four options plus Other, and a final result message.

`apps/backend/src/run-milestones.ts` writes `run_milestones`: an acknowledgement when an approval is queued, status text at most once every 3 seconds, a milestone for a blocker or a question, and a result that carries the pull request and proof refs. A room id calls `postRoomEvent`. That writer is a stub until the room owner replaces it. Approving a run claims `repo_work_claims`; a conflict returns three choices (queue, new branch, cancel). `GET /api/needs-you` merges approvals, pending questions, notification mentions and handoffs, and blocked runs. Blocked rows and progress text are limited to runs on the caller's orchestrator in the requested workspace. Tasks home progress text is the latest status row for those runs.
