## 2. Amount-aware team funding

**Implemented and pushed.** The native bootstrap deployment operator must also be a current workspace manager. Funding selects one member, employee version, model, input/output/request limits, expiry and explicit USD budget. Separate human activation, exact turn approval and Execute are required. Money uses integer microUSD, a 15-minute reference quote and a unique permanent per-turn ledger reserved atomically before at most one application-level `AI.run` call. The maximum full-context reservation is 8,341 microUSD for 131,072 input-context tokens plus 1,024 output tokens. Lower reported usage does not refund the reservation. Missing/invalid/unknown usage blocks further work; replay does not cause another debit/inference. Legacy amountless output can remain source-authorized but cannot dispatch new work.

This is an **application authorization estimate**, not an invoice cap, payment or provider-wide budget. Pricing changes, fees, taxes and infrastructure costs are excluded. It does not fund arbitrary CLI/specialist/automation/provider work, transfers, purchases or payroll; those require separate contracts and any pending spend decision remains intact.

**Evidence.** Final scoped Money v2 gate: 77 backend and 36 frontend tests; [nine actual Chromium HTTP-fixture checks](team-model-money-browser-20261105.json). Independent review reran 77 backend/35 frontend cases, then reproduced and verified the exact quote-expiry UI fix separately. No real inference, funding transaction or invoice reconciliation was performed. [Pushed contract](https://github.com/opentoolsorg/shiba/blob/2c5336fbe0988535c9023bd645a3b699d8330156/docs/team-model-sessions.md).

**Live prerequisites.** Explicit feature/model policy, verified operator and requester, reviewed funding and permission for one bounded billed test. Actual provider response/usage shape and deployed behavior remain unverified.

## 4. Replacement recovery

**Pushed evidence.** The [local journal drill](https://github.com/opentoolsorg/shiba/blob/2c5336fbe0988535c9023bd645a3b699d8330156/docs/local-journal-recovery.md) actually restarts workerd against persistent SQLite and reconnects over TCP, retains committed ACKs after lost replies, attaches the same surviving Node source without START, verifies redacted stdout/stderr hashes and reports 2,049-to-2,048 display retention loss explicitly. Its early-stop orphan regression was independently reproduced red, then green after guarded cleanup. The Container bridge/native identities remain fixtures.

**Integrated source implementation.** A separately approved output archive retains sanitized acknowledged payload outside the source container, independent of display pruning. It binds approval/input/job/epoch and an explicit read lease, reserves before execution, separates payload/source frontiers, and preserves unknown tails without relaunch. Limits: 8 MiB canonical UTF-8/8,192 events per job, room 16 MiB/two jobs, native owner 32 MiB/four jobs, absolute lifetime at most 24 hours; original source remains 4 MiB/4,096 frames. Uncertain quota is not recycled before expiry. The first slice admits only explicitly selected new direct native bootstrap-owner queue runs; profile/skill/goal/shared-context/team/local/personal/child paths are excluded.

**Evidence.** Both actual local workerd wrappers passed: the existing same-container drill and the new replacement drill, using persistent SQLite/D1 and real TCP transport. The replacement uses three runtimes, one source launch, zero replacement STARTs, ACK five retained while emitted frame six is unknown, revoked read denied and zero allowed external requests. Native Container claim/epoch remains a fixture. Final scoped gates: 21 archive/native integration cases, five settlement-retirement cases, 25 frontend cases including StrictMode, [eight Chromium HTTP-fixture checks](run-output-archive-browser-20261105.json), and five independent peer regressions. The [implementation record](../container-replacement-journal-proposal.md) now describes the implemented scope and its acceptance limits.

**Remaining boundary.** This recovers the committed sanitized prefix. It cannot recover process memory, uncommitted files, an unacknowledged pipe tail or prove successful settlement/artifacts/publication from text. No autonomous replacement command is authorized. Actual Cloudflare Container replacement, provider egress, the full Think/facet chain and shared/team archive authority need separate acceptance/contracts. Universal zero-dropped-source-byte recovery is not a supported claim.
