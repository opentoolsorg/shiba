## Remaining product contracts and external verification

- The v3 Ads operation needs an Ads-only runtime token. Its single configured parent token cannot simultaneously serve Figma/Linear; a distinct per-source token routing contract is required for coexistence. No wide token or fallback should replace that boundary.
- Meta Ads is not implemented. The pinned API-key-style provider cannot inherit OAuth standing authority; it requires its own explicit native credential/grant and fixed read contract.
- HubSpot–Stripe reconciliation requires a separately authorized HubSpot MCP read, explicit internal invoice-ID and comparable paid-amount/currency mapping, uniqueness policy and receipt-bound composition. Names, emails or deal values must not be treated as payment matches. Bounded or delayed searches do not establish global absence.
- Stripe reports are not automatically eligible for the existing OAuth-report Slack standing grant. Cross-family composition and disclosure require a new exact reviewed source contract.
- Real Cloudflare/provider/OAuth/installed Slack, computer allocation, source-replacement and paid model acceptance remain unverified. No preview or production deployment, real provider/model/Slack action, credential creation or financial transaction was performed for this extension.
