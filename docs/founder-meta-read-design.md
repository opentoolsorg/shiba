# Private bounded Meta Ads reads

This isolated Worker-only lane is disabled by default. It requires the separate `FOUNDER_META_CREDENTIAL_KEY` secret and `FOUNDER_META_READS_ENABLED=true`, migration 0029 and operator-reviewed configuration. Native routing, the serial scheduler and an explicitly opened workspace setup panel are wired in source; deployment and live acceptance remain unverified. No token, account, secret or external request is created by this implementation. All acceptance evidence uses synthetic tokens and mocked provider responses; live Meta access is not certified.

A native workspace manager creates a private draft for one numeric ad-account ID, an explicit seven-day inclusive interval, page limit, daily cadence, call cap and expiry. The creator attests that the token is appropriate for the intended `ads_read` access. Neither the token's form nor a successful account GET establishes its permissions, that it lacks write access, or legal ownership. Only two fixed GETs exist in this lane. The Worker encrypts the token using a Meta-specific key domain and associated data binding workspace, original native account UUID, credential ID, revision, ad account and expiry. The token is sent only in the Authorization header; it is never returned, logged or passed to a container.

Verification consumes one reserved call to `graph.facebook.com/v25.0/act_ID` with the fixed fields `id,account_id,currency,timezone_name`; returned identity must match exactly. Currency and timezone become part of a new frozen contract digest. The human must separately review this digest and consent to the exact daily reads and provider quota before enabling. Draft, verify, enable and revoke require the deciding native session at their database mutation; verification also rechecks that session before the provider request and clips its timeout to the session lease. An already enabled schedule does not require an open browser session. Lease is at most 28 days; at most eight calls including verification; each read is at most 25 rows, 32 KiB and five seconds. Each occurrence reserves quota and state before sending. Unknown outcomes hold the reservation and are not automatically retried. The source pin binds execution and contract code; a mismatch stops future use.

Insights use the single fixed account-level endpoint with `impressions,clicks,spend,account_currency,date_start,date_stop` and the frozen time range. A provider pagination URL is never followed or retained. Reports include only validated projection fields and explicitly say dataset completeness and business success are unknown; they are not reconciliation or provider invoices. Reads require the original native owner, exact account and current membership version; final database and synchronous expiry checks follow asynchronous work. Revocation erases ciphertext and stops future reads. Account removal or a remove-and-readd membership cannot revive an earlier grant.

The endpoint shape follows Meta's official [account detail](https://www.postman.com/meta/facebook-marketing-api/request/1uec83e/retrieving-adaccount-details-l4) and [account insights](https://www.postman.com/meta/facebook-marketing-api/request/u38qbri/get-insight-details-from-an-adaccount-l4) examples. The narrow implementation references the locally reviewed OpenConnector provider source at `d89dc9`; it does not import that generic provider executor.
