# Offline shared computers

This is a separate, default-off human desktop purpose. It does not attach to a coding run, paired personal computer, model or employee tool. Existing coding CLI work is never interrupted or transferred into it. The first slice uses a real Xvfb/Openbox/Chromium desktop with a bundled local notes page and **no Internet access**. It does not support authenticated websites, external applications, financial transactions, arbitrary URLs, uploaded files, provider credentials or account logins. General remote-computer parity is not claimed.

`SHIBA_SHARED_COMPUTER=1`, an optional `ComputerSession` Durable Object/container binding, the existing Worker-only `INTERNAL_SIGNING_KEY`, and `SHIBA_SHARED_COMPUTER_IMAGE` containing an exact registry digest are all required. The configured digest must equal the frozen creation image and the actual `ctx.container.images.computer` reference. Missing bindings, changed images or failed display readiness are unavailable, never successful empty screenshots. No Cloudflare resource or deployment is created by adding this source. Each runtime RPC requires a separate domain-scoped HMAC operation capsule binding the native actor, workspace, session/version/digest, exact operation/input and at most ten seconds of validity. The DO verifies and consumes it durably once before protected reads or effects; guessed/replayed parameters confer no runtime authority. Alarm destruction uses a private method. No signing key enters the image or RPC capsule.

## Human authority and funding

`/api/shared-computers` accepts a verified native cookie and explicit `X-Shiba-Workspace`; bearer/agent authority is rejected. A room owner prepares a draft selecting current verified native room members, at most eight viewers and a named controller subset. The draft freezes the exact native UUIDs, workspace membership versions, room membership creation/capabilities, room identity, image, offline purpose, resource limits and expiry. It imports no parent transcript, shared memory, files or credentials. Slack-linked rooms are unavailable for this purpose.

The selected **bootstrap operator who is also a current workspace owner/admin** must separately review the complete draft and give explicit deployment-billing consent. Workspace ownership, invitations, model funding and personal subscriptions do not confer this authority. The source owner then reviews the same digest and explicitly consents to sharing the complete screen before starting it. These are human HTTP actions; no employee/MCP tools, agent approval, model dispatch or automatic activation are registered.

There is one allocated or uncertain desktop **across the deployment**. The one-shot reservation is consumed before the start RPC. A lost acknowledgment does not refund the reservation, extend expiry or automatically relaunch. Capacity remains occupied until dedicated destruction is confirmed. Each new session requires new human approval. The maximum TTL is ten minutes from preparation; the fixed profile is `standard-1` (0.5 vCPU, 4 GiB memory, 8 GB disk). The reviewed estimate is resource-only overage arithmetic; account base charges, DO/Worker/storage/network use and billing-unit rounding are additional. It is not a hard invoice cap. The [Cloudflare reference rates](https://developers.cloudflare.com/containers/platform/pricing/) checked on November 5, 2026 are $0.000020 per active vCPU-second, $0.0000025 per provisioned GiB-second and $0.00000007 per provisioned GB-second; the estimate assumes full CPU use and no included allowance.

Any approved named controller may claim the single exclusive lease, at most sixty seconds and never beyond the session expiry. Every input binds the session/digest, lease version, monotonically increasing sequence, request UUID and exact action hash. Claimed inputs are not retried after lost acknowledgment. Raw typed text and screenshots are not stored in audit rows. Inputs use fixed argv, never a shell: bounded coordinates, a small key enum, at most five scroll ticks, at most 1,024 UTF-8 text bytes, 300 inputs/session and 100ms minimum spacing. Text is screened using existing secret-pattern rules, which are not universal DLP. Do not enter credentials or data outside the selected display audience.

## Privacy, expiry and failure handling

A synchronous durable retirement tombstone fences a completed STOP before any older awaited proof can allocate, send input or return a capture. It reloads on DO reconstruction; no stopped generation is revived. Source/native membership and lease checks run again after asynchronous work and immediately before input dispatch. Room removal/re-add permanently invalidates the old generation. Current source checks also protect each capture and its return. Native account replacement, funding revocation, expiry, image changes and authorization failures block new input/capture. An input already sent cannot be retracted; its uncertain result is retained and not replayed.

Capture is an explicit authenticated `POST /sessions/:id/capture`, not a public desktop/preview/VNC/CDP endpoint. It returns a complete bounded JPEG with `Cache-Control: no-store, private`. It includes the actual OS pointer; independent multi-cursor presence is not implemented here. Screenshots are not written to R2 or a shared thumbnail cache. Global capture limits are one/second, 120 attempts and 16 MiB reserved per session, with a 512 KiB limit per frame. Reserving the full maximum before capture means that the total byte cap can end capture before 120 attempts. Sampling does not promise lossless video.

The isolated image has no coding/provider CLIs or host mounts. `enableInternet:false` has no allow rules or outbound credential handler. X11 listens only inside the container. The image watchdog terminates the desktop at its fixed expiry; a DO alarm independently stops expired/revoked generations, and a thirty-second inactivity timeout limits orphan runtime. A verified immutable native owner/funder can use the narrow STOP route after membership revocation; STOP confers no read, control, renewal or allocation authority and affects only this dedicated desktop. Unknown destruction retains the occupied slot.

Cloudflare documents that Linux `user` IDs do not isolate processes under `durable_object` scheduling. The separate VM and absent credentials are the boundary; fresh HOME, browser flags and process user IDs are not claimed as security sandboxes. See the [Container API](https://developers.cloudflare.com/containers/api/durable-object-container/) and [outbound controls](https://developers.cloudflare.com/containers/configuration/outbound-traffic/).

## Image provenance and local verification

`apps/backend/Dockerfile.computer` pins the official Debian linux/amd64 image manifest `sha256:a3bba7dc7dbcc1f37c2856c51fc9a7fac96608f50cb87b1b4e4d8b8c85ae988e`, the SDK 1.0.1 shim image `sha256:e796e813de8213fb062bba279ddeddbf61277389a2cc7b3e4620075a9188843b` and Debian package snapshots at `20261105T000000Z`. Tags cannot silently move these inputs. The image retains `/usr/share/shiba-computer/packages.tsv` plus package copyright files. The session proxy CA is mounted only while building, with TLS and signed APT metadata verification enabled; it is not copied into a runtime layer.

The installed Cloudflare SDK/shim is Apache-2.0. [xdotool](https://github.com/jordansissel/xdotool/blob/main/COPYRIGHT) has BSD-style three-clause conditions; [scrot](https://github.com/resurrecting-open-source-projects/scrot/blob/master/COPYING) has MIT-style attribution terms; [Openbox](https://github.com/danakj/openbox/blob/main/COPYING) distributes GPLv2 text; [Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/LICENSE) has BSD-style first-party terms and additional bundled notices. The [X.Org license inventory](https://www.x.org/releases/current/doc/xorg-docs/License.html) requires per-file/package verification. Preserve the actual distribution copyright/source obligations; this inventory is not blanket legal clearance.

Local Docker builds/tests use the managed daemon and build-only proxy trust. Runtime acceptance must use `--network none`, explicit resource/PID bounds, no bind mounts, no credentials and a short fixed expiry; Docker client proxy defaults must be cleared for that runtime. The existing `docker-local` sandbox adapter uses host networking and is deliberately not reused. Local Docker, fake Container/Files fixtures and real SQLite tests are separate from Cloudflare execution. No live deployment, remote desktop, model/provider call or Cloudflare container start is established by these local checks.


## Verification boundary (2026-11-05)

The focused backend suite runs actual routes, SQLite and the dedicated DO class with fixture Container/Files transports; it covers scoped operation capsules, authority changes, unknown acknowledgments, control/input/capture bounds and abort-ignoring transport deadlines. Frontend/client cases and the [Chromium evidence](verification/shared-computer-browser-20261105.json) cover the explicit review flow, source isolation, manual synthetic-image capture, 390px themes and retained STOP. Chromium checks use intercepted HTTP and a clearly labeled synthetic JPEG, **not a functioning desktop, real native login, funding or Cloudflare runtime**. The source hashes are retained in that report.

Two local pinned image builds failed on signed Debian snapshot package fetches returning HTTP503/504 through the managed proxy, after the public build CA permissions were corrected. TLS verification and package signatures were not bypassed. No desktop was started; actual display readiness, toolkit compatibility, final installed package/license manifest and offline input/screenshot/expiry behavior remain unverified. The feature must remain unavailable/default-off until the image builds and those local/Cloudflare acceptance checks pass. No replacement image, host-network runtime or successful computer session was substituted.


CI can build without pushing, then run the separate actual-image acceptance command:

```sh
env -u DOCKER_HOST -u DOCKER_CONTEXT -u DOCKER_TLS -u DOCKER_TLS_VERIFY -u DOCKER_CERT_PATH \
  docker --host=unix:///var/run/docker.sock build --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt -f apps/backend/Dockerfile.computer -t shiba-computer-offline:ci apps/backend
node apps/backend/computer/verify-offline.mjs --image shiba-computer-offline:ci --output /tmp/shiba-computer-evidence
```

In the managed executor preserve its configured build proxy/CA and explicitly select the local Unix Docker daemon, as required by the environment instructions. The verification driver always selects that Unix socket, resolves the tag to an immutable local image ID, clears runtime proxy defaults, starts only its own UUID-named offline container with 0.5 CPU/1 GiB/PID256/read-only root/tmpfs bounds, captures real before/after JPEGs, checks installed notices and waits for the fixed sixty-second watchdog. It removes only that container, including uncertain `docker run` acknowledgment cases. Six pure driver safety tests check arguments/scope; they are not actual-image acceptance. Raster changes and an acknowledged xdotool command do not alone certify DOM text; the retained actual JPEG permits visual verification. A twenty-minute cold-build CI budget is appropriate; the local snapshot failures exceeded seven minutes. No successful actual-image run has yet been observed.
